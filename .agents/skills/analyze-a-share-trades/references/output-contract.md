# 分析输出契约

本文件定义用户最终应看到的交易结论。内部分析可以很完整，最终输出只保留影响当前动作的内容。

## 一、基本原则

1. 结论置顶，先回答买入、条件买入、等待、持有、减仓、卖出或不交易。
2. 买入筛选可以得到零只、一只或多只值得买的股票；不强制排名、首选或备选。
3. 每只股票独立说明名称、代码、值在哪里、主策略以及买入、持有和卖出安排。
4. 内部必须检查冲突证据和替代解释；最终只展示会改变动作的重要风险或冲突，不设置“最大反证”固定栏目。
5. 不固定输出乐观/基准/悲观三情景；只有情景分支确实帮助执行时才按需使用。
6. 不输出主观胜率、上涨概率、赔率百分比、固定综合分或由模型随意设定的排名。
7. 事实、综合判断和行动分开，不能把“洗盘”“主力吸筹”“产业核心”等推断写成直接事实。
8. 没有合格股票时明确说“当前没有值得买的股票”，不得为满足用户而降低门槛。
9. 行动之后必须给出“大盘层 → 板块层 → 个股层”的意图链和主要耦合方式；每个决策对象只展示一个主假设和一个竞争假设。
   - 分析具体股票时，这两个假设是两条完整的三层路径；大盘快照只是上游输入，不再为大盘、板块、个股各展开一对假设。
10. 两个假设无法可靠区分时直接写“意图不知道”。未持仓建议保持空仓；已有持仓在用户要求动作时建议按可执行规则退出至空仓。说明这是证据不足或冲突下的风险偏好，不是断言价格必跌。
11. 用户在获知“不知道、默认空仓”后仍明确要求继续时，可以输出纯数据/事件降级分析，但必须置顶披露无法可靠判断主导资金意图，且不得把数据结论改名为主力判断。

## 二、分析基准与 D1

### 1. 分析基准

每次正式交易结论显示：

```text
分析基准：YYYY-MM-DD HH:MM（北京时间）
行情截至：仅在与分析基准不同、存在延迟或多组数据截止不一致时显示
```

此前对话中的时效性结论只作历史语境。新的问询必须按本次 `analysis_as_of` 重新核验当前市场、主线、板块、事件和个股状态：

- 不计算距上次分析经过了几个交易日。
- 不展示原策略/新策略、原触发状态或原策略是否到期。
- 不写“原策略失效/恢复/到期”“旧结论重新生效”等生命周期措辞，也不专门说明如何从旧策略切换到新策略；只需说明旧时效性内容未被当作当前事实，然后直接给本次判断。
- 不因对话仍在同一任务中而沿用旧的“当前”结论。
- 同一交易日复用大盘意图快照时，必须做新鲜度检查并显示快照 `as_of`；该检查可以完成大盘层重核验，不要求为每只股票重新完整取数。
- 成本、仓位、用户风险偏好和原始买入理由等仍然有效的用户事实可以继续使用。

### 2. D1

- 提问当日为交易日时，当日为 D1，不区分盘前、盘中或收盘后。
- 提问当日为非交易日时，其后的首个交易日为 D1。
- D1 收盘后只能给下一交易日执行方案时，写“从 D2 开始”，不重新编号。
- 股票停牌等硬限制使执行更晚时，写“待恢复交易后重新分析”，不把未来自然日期展示给用户。
- D1 只锚定本次未来行动、持有和复核，不限制历史回看范围。

不得计算、询问或输出已有持仓的已持有天数。

### 3. 持有窗口

只有在用户询问持有期，或持有窗口会帮助执行时才显示：

```text
基础持有窗口：D1—Dn
中途复核：Dn
提前退出：可观察的价格、板块、事件或策略条件
```

尚未买入时写“条件成立并实际成交后的基础窗口”，不得伪装成已经持仓。等待或不买时不必虚构持有期。

## 三、全市场选股

### 1. 必须展示候选是如何产生的

用简洁语言交代：

```text
大盘层主导合力意图与市场状态
→ 大盘和板块的耦合方式
→ 板块资金意图与主线/次主线/轮动/退潮
→ 产业链和资金迁移
→ 龙头、核心、中军和跟随梯队及其反馈
→ 沪深主板硬过滤
→ 待深析候选
→ 个股层主导资金意图假设
→ 综合筛出的值得买股票
```

不需要逐项展示所有中间数据，但不能直接从几千只股票跳到一个代码而不说明候选来源。

### 2. 不强制排名

根据综合分析将股票分为：

- `值得买`：当前已有清晰交易逻辑和可执行策略；
- `条件值得买`：逻辑成立，但需等待价格、板块、事件或盘面条件；
- `暂不买`：可以说明重要关注对象为何没有通过，但不必列出全部被淘汰股票；
- `当前无值得买股票`。

同一类别内不强制顺序代表质量排名。用户明确要求只选一只时，才在当次回答中比较并给出取舍。

### 3. 每只值得买或条件值得买的股票

至少包含：

```text
股票：名称（六位代码）
当前判断：值得买 / 条件值得买
主策略：
值在哪里：
为什么是现在：
大盘 → 板块 → 个股意图链：
三层耦合：
主假设：
竞争假设：
下一确认与失效条件：
龙头/板块/产业角色：
买入策略：
持有与加减仓：
卖出策略：
若 D1 未执行：D2 开始的条件预案
会实质改变动作的风险：仅在存在时显示
```

“值在哪里”必须是当前交易价值，而不是只复述公司长期故事。综合市场、资金、主线、产业、龙头、事件、量价、历史行为和人性博弈，不按固定权重排序。

多只股票可以分别使用不同主策略；单只股票只能锁定一个主策略。

## 四、指定股票与持仓

### 1. 指定股票是否值得买

第一行直接写：

> 股票名称（六位代码）：值得买 / 条件值得买 / 空仓 / 等待 / 不买

随后按实际影响说明：

- 是否通过股票池硬过滤；
- 当前市场与主线环境；
- 产业和公司受益关系；
- 产业龙头、盘面龙头、情绪龙头、趋势核心/中军或跟随角色；
- 事件对当前逻辑的影响；
- 资金、日周线、分时和主力/人性博弈；
- 大盘、板块与个股的意图链、主要耦合方式、主假设、唯一竞争假设和下一确认；
- 主策略和为什么是现在；
- 买入、持有、加减仓和卖出安排；
- 涨跌停时的 D1 尝试和未执行后的 D2 预案。

不要求机械列出反例、最大反证或固定三情景。若某项负面证据会改变动作，必须自然写入判断或风险。

### 2. 已有持仓

第一行使用：

> 股票名称（六位代码）：继续持有 / 持有但不加仓 / 减仓 / 条件卖出 / 卖出 / 退出至空仓

按需说明：

- 用户成本、仓位和原始买入理由是否已知；
- 原始逻辑当前是否仍成立；
- 市场、主线、产业角色、事件和龙头地位发生了什么变化；
- 大盘、板块和个股层分别更可能在做什么，两层之间如何耦合；
- 主假设、唯一竞争假设、下一确认与失效条件；
- 当前日线、分时、主导资金行为和人性博弈如何影响动作；
- 当前卖出/持有策略；
- 实际成交后的下一步；
- D1 未执行时从 D2 开始的条件预案；
- 若继续持有，基础窗口和复核点。

用户未提供成本、仓位或买入理由时仍可给市场结构层面的动作倾向；只有精确账户动作确实依赖这些信息时才请求。不要索要买入日期来计算持有天数。

## 五、事件如何进入结论

公告、业绩预告、政策和其他事件不是单独任务模式。事件部分回答：

- 事实发生了什么；
- 相对预期是强化、基本符合、低于预期还是无法判断；
- 一次性还是可持续；
- 公告前是否已经提前交易；
- 对主线、产业、龙头地位、量价和主力/人性博弈的影响；
- 最终是否改变当前交易动作和策略。

最终可以自然写成：

> 业绩预增强化了主营景气逻辑，但公告前已经加速且板块没有扩散，因此事件偏正面，当前交易动作仍是等待分歧承接。

不要写成：

> 业绩预增是利好；事件建议是买入。

历史事件结论只在先定义筛选规则并纳入全部符合条件的样本后使用。样本不足时不形成稳定画像。

## 六、涨跌停与执行

### 1. 决策顺序

涨跌停价不等于订单必然无法成交。无需在策略判断前确认个别订单能否成交，按以下顺序：

```text
先假设能够成交，完成 D1 交易判断
├─ D1 应交易
│  ├─ 给用户尝试交易的策略
│  ├─ 实际成交：进入成交后的持有/退出策略
│  └─ 未成交或部分成交：按真实仓位进入 D2 条件预案
└─ D1 不应交易，或已无用户可使用的适用交易时段
   └─ 直接给 D2 开始的条件预案
```

不建立涨跌停可交易性三态。常规连续竞价已经收盘时，先核验盘后固定价格等适用机制；仍可执行就给 D1 尝试方案，不能仅凭“已收盘”机械跳到 D2。

### 2. 输出方式

涨跌停场景按需使用：

```text
假设能够成交，D1 判断：买入 / 卖出 / 持有 / 不交易
D1 策略：若应交易，说明如何尝试；不保证成交
实际成交后：
若 D1 未执行或只部分执行：D2 开始如何观察和处理
```

- 涨停买入先判断是否值得买；值得时可以按策略尝试，不值得时直接给 D2 条件。
- 跌停卖出先判断是否应该卖；应该时可以尝试，不承诺成交；未成交时给 D2 处理。
- 不把挂单或提交委托写成已经成交。
- 下一次分析以用户报告的实际成交、部分成交和真实仓位为准，Agent 不猜成交结果。
- D2 预案是基于未来可观察条件的计划，不是提前承诺次日开盘必买或必卖。

### 3. 硬性不可执行例外

停牌、普通 A 股当日买入后受 T+1 限制不能卖出、账户明确没有证券或资金等已经确认的制度/账户事实可以直接写为硬限制。涨跌停本身不属于该类硬限制。

## 七、建议输出顺序

### 1. 结论卡

```markdown
## 结论

- 分析基准：
- 大盘快照截至：仅在复用同日快照时填写
- D1：
- 动作：
- 股票：名称（代码）/ 多只见下 / 当前无值得买股票
- 主策略：单股问题填写；多股分别填写
- 意图状态：可判断 / 不知道 / 纯数据事件降级
- 一句话理由：
- 数据限制：仅在会影响动作时填写
```

### 2. 三层意图与候选来源

全市场筛选时简洁回答：

- 大盘层的主假设、竞争假设、预期动作序列与失效条件；
- 当前市场、风险偏好及大盘快照是否复用；
- 板块层资金意图及其与大盘的耦合方式；
- 资金、情绪和赚钱效应；
- 主线、次主线、轮动和退潮；
- 产业链、资金迁移和龙头梯队；
- 候选池如何从上述方向与沪深主板硬过滤交集产生。

指定股票问题只展示会影响该股的部分。

### 3. 股票结论

逐只写：

- 名称和代码；
- 值得买、条件值得买、空仓、等待或不买；
- 大盘—板块—个股意图链和主要耦合方式；
- 一个主假设、一个竞争假设及下一确认；
- 值在哪里和为什么是现在；
- 龙头/产业/盘面角色；
- 事件、量价和博弈的综合影响；
- 买入、持有、加减仓和卖出策略；
- D1 未执行后的 D2 预案。

### 4. 必要风险和数据缺口

只写会改变当前动作、需要用户补充或必须防范的内容。不为模板完整重复所有常规风险。

## 八、数据不足

先写能够形成的暂定结论，再精确请求缺少的资料：

```markdown
## 暂定结论

- 分析基准：
- 股票及当前倾向：
- 意图状态：
- 已具备资料：
- 当前只能判断到哪一层：

## 仍需补充

1. [具体资料]：用于判断什么；
2. [具体资料]：用于判断什么。
```

- 有日线、缺分时：可以给日线级判断，不给即时盘中动作。
- 有事件原文、缺市场预期：可以说明事实方向，不能断言超预期。
- 有个股分时、缺板块和龙头对照：不能确认盘面核心或独立强势。
- 已有合格资料不得重复索要。
- 数据不足不自动等于看空；只有当缺失项使主假设与竞争假设无法区分时，意图状态才是“不知道”，并按用户偏好建议空仓或退出至空仓。

用户在看到上述边界后仍明确要求继续时，使用：

```markdown
## 纯数据/事件降级分析

> 无法可靠判断大盘、板块或个股主导资金意图。以下只分析可验证的数据、事件和价格结构，不代表已识别主力意图。

- 数据与事件事实：
- 价格和量能结构：
- 可以得出的条件判断：
- 不能据此判断的内容：
- 风险基准：空仓；如用户进一步明确要求数据驱动条件策略，再写触发与失效条件
```

降级分析不得悄悄恢复“洗盘、吸筹、派发”等意图标签，也不得因用户坚持而补造缺失数据。

## 九、禁止输出

- 强制选出第一名、首选或备选；
- 用证据完整度、固定权重或综合分直接排列最终股票；
- 为了必须给股票而忽略“不买”；
- 只说板块而不在买入筛选中给出股票名称和代码；
- 把事件另立为与当前交易割裂的操作结论；
- 从记忆挑选几个历史案例充当完整事件样本；
- 把特殊时段成交直接归因于散户、机构或主力；
- 把公开量价写成识别了真实主力账户和确定意图；
- 同一决策对象输出两个以上竞争假设，或为每层分别扩写多套故事；
- 两个假设无法区分时强行选边，或隐藏“意图不知道”；
- 意图不知道时仍建议新开仓，或把空仓规则写成价格必跌判断；
- 未经用户在知情后明确坚持，就进入纯数据/事件降级模式；
- 在降级模式中继续使用“主力已吸筹/洗盘/派发”等确定性意图措辞；
- 把一字涨停直接写成必然买不到，或把一字跌停直接写成必然卖不掉；
- 先输出涨跌停可交易性状态并据此跳过应不应该交易的判断；
- 把提交委托写成已经成交；
- 给 D2 无条件自动追涨或无视新信息的预承诺；
- 输出主观胜率、赔率百分比或保证收益；
- 没有分析基准就使用“当前”“今天资金”等时效性措辞；
- 沿用旧对话中的当前结论而不重新核验；
- 把跨天连续问询写成原策略失效、恢复、到期或切换的状态机；
- 计算或输出已有持仓的已持有天数；
- 将未来 D1—Dn 换算成自然日期展示；
- 对合格资料重复提出请求；
- 在行情延迟时给出虚假精确的即时成交指令。

## 十、最终自检

- [ ] 已展示北京时间 `analysis_as_of`，旧时效性结论未被当作当前事实，也未输出旧策略生命周期；
- [ ] D1 定义正确，未计算跨问询天数或已持有天数；
- [ ] 全市场选股交代了市场到候选池的生成链；
- [ ] 候选经过沪深主板、ST、停牌和流动性硬过滤；
- [ ] 龙头类型和动态地位已纳入综合分析；
- [ ] 值得买股票可以为零、一只或多只，未强制排名；
- [ ] 每只股票独立选择一个主策略；
- [ ] 事件已融合进当前交易判断，没有另起割裂模式；
- [ ] 历史事件先定规则并纳入全部符合条件的样本；
