本文件规定分析时可以使用哪些数据、如何记录时间、何时降级，以及如何使用 DeepSeek。任何买卖结论都必须先满足本文件的数据约束。

## 1. 基本原则

1. 先确定分析时点，再取数，禁止使用分析时点之后才产生或发布的数据。
2. 结构化数据负责事实和计算；网页与公告原文负责核验；截图仅在结构化行情缺失时补充视觉证据。
3. 对每项关键事实记录来源和时间。数据不足时降低结论强度，不得让模型补全缺失事实。
4. “主力资金净流入”等数据商字段只是按成交特征计算的代理指标，不等于识别出真实机构或主力账户。
5. 模型输出只能生成摘要、分类、映射或假设，不能替代行情、公告、财务报表等原始事实。
6. D1 只定义本次未来行动窗口，不是历史数据截断点。必须保留并使用 `analysis_as_of` 之前与结论相关的历史数据。
7. “历史主力风格”只能写成主导资金行为画像：必须来自重复的公开量价样本，不得声称识别真实参与者或确定意图，也不得替代原有多维判断。
8. 每次正式分析使用新的 `analysis_as_of`。先前对话中的“当前主线”“现在可以买”“主力正在吸筹”等时效性结论不得直接沿用，必须按本次分析基准重新核验；不计算两次问询相隔的交易日，也不维护或输出“旧策略失效、恢复、到期、切换”等旧结论生命周期，直接生成本次判断。

统一使用 `Asia/Shanghai` 时区；时间戳采用带时区的 ISO 8601 格式，例如 `2026-07-27T10:35:00+08:00`。

必须把本次分析的 `analysis_as_of` 与数据自身的 `as_of`、`fetched_at` 分开记录。任何分钟线、日线或其他 bar 的时间戳晚于 `analysis_as_of` 时，必须在计算特征前剔除；若来源返回了这种记录，报告中说明剔除数量、时间范围及可能的时间戳语义或时钟偏差，不能把它解释为已发生事实。历史回放和盘中复盘必须使用显式 `analysis_as_of`，不得以运行脚本时的机器当前时间替代。

## 2. 每条数据必须记录的时间字段

关键数据至少保留以下字段：

| 字段 | 含义 | 示例 |
|---|---|---|
| `as_of` | 数据实际描述到哪个时点或报告期 | 分钟线最后一根为 `2026-07-27T10:30:00+08:00` |
| `published_at` | 来源正式发布该信息的时间；来源未提供时为 `null` | 公告披露时间 |
| `fetched_at` | 本次获取或读取数据的时间 | API 返回完成时间 |
| `freshness` | 根据任务和当前时点判定的新鲜度等级 | `realtime`、`delayed`、`stale`、`unknown` |
| `source` | 数据源及接口、网页或截图名称 | `AkShare/stock_zh_a_hist` |
| `observed_or_inferred` | `observed` 表示直接事实，`inferred` 表示推断 | 分时价格为事实，洗盘为推断 |

不要用 `fetched_at` 代替 `as_of`。例如 10:40 获取到最后更新于 10:15 的行情，`fetched_at` 是 10:40，`as_of` 仍是 10:15。

### 2.1 `freshness` 判定

对盘中价格、成交量、分时、板块涨跌等高频数据：

- `realtime`：与当前市场时间相差不超过 1 分钟。
- `near_realtime`：相差大于 1 分钟且不超过 5 分钟。
- `delayed`：相差大于 5 分钟且不超过 30 分钟。
- `stale`：相差超过 30 分钟，或缺少当日更新。
- `unknown`：无法确定 `as_of`。

对日线、财务、公告、宏观数据，不套用上述分钟阈值，应按其自然更新周期判断：

- 日线必须来自最近一个已经完成的交易日。
- 盘中返回的当日日线仍是未完成记录；应依据 `analysis_as_of` 排除或明确作为盘中快照处理，不能因脚本在收盘后运行就将其回填为当时已知的完整日线。
- 财务数据必须标记报告期与公告时间。
- 公告和新闻必须标记首次发布时间，避免把旧消息当作当日催化。
- 月度宏观数据必须标记统计期，不得称为“实时资金面”。

## 3. 数据源路由

先定义本次决策缺少的事实，再按覆盖范围、时效、可靠性、数据量、权限和调用成本选择来源。以下来源是可组合能力，不是每个问题都要执行的固定优先级链。一个质量合格的来源通常已经足够；关键事实、来源冲突或质量存疑时再交叉核验。

### 3.1 AkShare

适合：

- 沪深行情、指数、日/周 K 线、成交额、换手率；
- 涨跌停、炸板、板块和个股资金代理指标；
- 新闻、公告索引、业绩预告、解禁、增减持；
- 财务摘要、估值、龙虎榜、两融；
- 汇率、商品及部分宏观数据。

执行要求：

- 仓库根目录的 `akshare_api_reference.md` 只是接口候选目录，不是凭证或每次分析的必读文件；仅在现有适配器缺少接口或需要核对函数名时读取，并以项目虚拟环境中实际安装版本的函数签名和返回字段为准。
- 调用前后检查字段是否变化、结果是否为空、日期是否覆盖目标时点。
- 对实时行情默认考虑 15—30 分钟延迟，除非返回值可以证明更及时。
- A 股现货使用 `fetch_market_data.py --dataset snapshot` 时，`--ak-provider auto` 按东方财富 → 腾讯 → 新浪的固定顺序各尝试一次；指数现货使用 `--dataset index-snapshot` 时按新浪 → 东方财富各尝试一次。元数据中的 `provider`、`attempted_apis` 和 `fallback_used` 必须保留。
- 自动故障切换不得重复整条提供方链；单一提供方或其他接口也只允许有限重试。全部失败后切换 Tushare、权威网页或截图，不得静默复用旧值。
- 资金流字段统一称为“资金流代理指标”，不得据此断言具体主体在买卖。

### 3.2 流动性日线聚合

- 对已有合并日线 CSV 或逐股票 CSV 目录，运行 `compute_liquidity_median.py`，只纳入分析时点前已经完成的交易日。
- 将输出按 `code` 合并回含名称、证券类型和交易状态的证券主数据后再运行股票池过滤；流动性聚合表本身不能证明非 ST、未停牌或属于主板。
- 普通 `amount` 字段必须核对单位；脚本可识别人民币显式字段和 Tushare `ts_code`/`trade_date` 的千元口径，其他自动假设会写入元数据。
- 网络补数必须先提供 `--codes` 或 `--candidates`，并只对缺少完整窗口的明确候选逐只抓取；禁止从全市场名单开始盲扫。
- 同一代码同一日期的成交额来源冲突时，正式流动性核验失败，不得选择对结论有利的数值。

### 3.3 Tushare

适合：

- 证券主数据、交易日历；
- 结构化日线、财务、公告和行业分类的补充或复核；
- AkShare 缺失或字段不稳定时的补充来源。

执行要求：

- 已初始化且能满足本次需求时，优先调用 Tushare 官方 MCP。
- Tushare Python API 保留为兜底。当 MCP 不可用、调用失败、权限或接口覆盖不足，或不适合本次批量计算、数据量和性能需求时，由 Agent 根据当前任务改用 API 脚本；不要按问题类型预先写死切换条件。
- 同一事实已由 MCP 返回且质量合格时，不再通过 API 重复抓取。MCP 与 API 结果冲突时，先比较接口、参数、复权、单位和更新时间，再决定复核方式。
- 先检查接口权限、积分、返回字段和更新时间；没有权限时直接降级，不猜测结果。
- 同一字段若与 AkShare 冲突，比较复权口径、单位、报告期和更新时间；无法消除冲突时并列披露，不自行选取更“符合观点”的数值。

### 3.4 网页与原始文件

优先用于：

- 交易所、上市公司、监管机构的公告原文；
- 政策文件、官方统计和公司财报；
- 产业链、产品、客户、产能与市场份额的事实核验；
- 美国、韩国、香港、日本、台股市场、欧洲及商品数据的缺口补充。

网页核验顺序：

1. 交易所、监管机构、政府或上市公司原文；
2. 指数公司、数据提供方或行业组织；
3. 可靠财经媒体；
4. 社交平台或博主内容只能作为待验证线索，不作为关键事实的唯一来源。

记录页面标题、链接、`published_at`、`fetched_at`。转载文章应尽量追溯首发来源和首次发布时间。

### 3.5 用户截图

当无法获得可靠的当日行情、分时或盘口数据时，应直接向用户索要截图，并说明缺失数据会影响哪项判断。截图是用户在特定时点提供的观测，不自动等同于实时结构化数据。

#### 单只股票买入或卖出分析

优先索要：

1. **当日分时图**：必须清晰显示股票名称、六位代码、日期、当前时间、价格轴、成交量、均价线和完整已交易时段。
2. **日 K 图**：前复权，至少覆盖最近 120 个交易日，建立历史行为画像时优先覆盖 250 个交易日；显示成交量及 5/10/20/60 日均线。
3. **所属板块分时图**：与个股截图时间尽量一致。
4. **市场指数分时图**：至少上证指数和深证成指；若个股明显属于特定风格，再补中证 1000、沪深 300 等适当指数。
5. 涉及持仓卖出时，补充持仓成本、仓位比例和买入理由；不为计算持有天数索要买入日期。不愿提供时可隐去账户金额，只保留百分比和成本。

需要判断竞价时，再索要：

- 9:15—9:25 的竞价走势或竞价详情；
- 匹配量、未匹配量、开盘价和撤单变化（界面能提供多少就提供多少）；
- 同板块核心股的竞价情况。

截图要求：

- 不要只截局部 K 线或只给一根分时线；
- 不要裁掉代码、日期、坐标和成交量；
- 多张截图标明拍摄顺序和时间；
- 截图过旧或时间不明时，标记为 `freshness: unknown`。

如果用户只能提供一张图，优先索要“名称代码与时间完整的当日分时图”；但此时不得给出精确到分时价位的高置信建议。

#### 历史行为画像的数据要求

- 至少使用 120 个已完成交易日，优先 250 个交易日；分别观察 120～250 日、20～60 日和 5～20 日层次。
- 在查看结果前定义事件/行为类型、时间范围、日线位置、市场与板块阶段、必要字段和客观排除条件，再纳入 `analysis_as_of` 之前所有符合规则且可得的样本。
- 所有合格样本不足 3 个时可以描述个案，但不得形成稳定历史画像；不得只选择三个支持当前观点的案例。
- 有历史分钟数据时，比较竞价、开盘前 30 分钟、VWAP、午后和尾盘；只有日线时明确标为“日线级画像”。
- 对除权除息、停复牌、股本与主要股东变化、重大资产重组等结构变化分段处理，旧样本不得无条件外推。
- 当前行情与历史画像冲突时，保留冲突并降低置信度；当前硬事实和风险规则优先。
- 历史样本日期、公告日期和数据 `as_of` 可以且应当用于证据追溯；“不输出自然日期”只针对未来持有、最早执行和复核安排。

## 4. 交易时段报告

先识别当前处于哪种时段，再加载相应数据。不同报告不可混用未来数据或不同机制的成交。

### 4.1 盘前版

可使用：

- 最近一个已完成交易日的 A 股收盘数据；
- 截至当前已发布的公告、新闻和政策；
- 隔夜美股及已结束或正在交易的海外市场数据，并标记各自 `as_of`；
- 9:15—9:25 集合竞价数据，但仅在该阶段完成后才能使用。

不得使用：

- 当日尚未发生的开盘价、全天成交额、涨跌家数或收盘数据；
- 将前一日资金数据描述为“今日流入”。

盘前结论使用条件式表达，例如“若 D1 开盘后板块放量且个股站稳某位置，则进入候选”，不能把未发生的条件写成事实。

### 4.2 盘中版

必须记录精确 `as_of`，并将以下内容分开：

- 已完成的历史日线；
- 截至 `as_of` 的当日分时、成交额和市场宽度；
- 根据当前节奏推断的全天数据，若使用必须明确标注“估算”，不得伪装成最终值。

盘中建议还必须检查：

- 当日买入受 T+1 限制，不能计划当日卖出；
- 停牌等已经确认的硬限制；
- 涨跌停时先假设能够成交并判断 D1 应不应该交易；应交易时给尝试方案，未成交或部分成交时给 D2 条件预案，不输出可交易性三态。

### 4.3 收盘后版

只在正式收盘数据完整后使用：

- 当日完整 OHLC、成交量、成交额、换手率；
- 全市场宽度、涨跌停与板块强度；
- 当日分时结构和尾盘行为；
- 收盘后已发布的公告另行标记，不能假设其已经反映在当日价格中。

常规交易收盘后，先核验该证券、该账户和本次动作是否仍有适用的盘后固定价格或其他交易时段。若没有，才形成下一可执行交易日的计划；若仍有，按该机制的价格、申报、撮合和参与规则给 D1 尝试方案。不得在没有适用机制时把收盘价写成仍可成交的即时买入价。

### 4.4 盘后固定价格与其他特殊时段

先区分收盘集合竞价、盘后固定价格、盘后定价大宗交易、协议大宗交易以及数据商在收盘后更新的日内统计，不能统称为“盘后交易”。

对每种机制记录：

- 现行交易所规则和规则生效时间；
- 适用品种、申报与撮合时间；
- 价格形成方式；
- 允许的投资者/交易参与者范围；
- 行情是否包含申报、成交或只包含汇总统计。

解释原则：

- 若机制只覆盖特定参与群体，只能直接解释该群体行为；对未参与资金的意图只能结合下一常规交易时段作间接判断。
- 若个人、机构和其他交易参与者均可能参与，成交信息覆盖面更广，但公开数据仍不能识别具体账户类型或“主力意图”。
- 参与规则或数据性质不清时，不作散户、机构或主力身份归因。

截至 2026-07-28，沪深交易所现行 2026 年交易规则均已把盘后固定价格交易适用品种扩展至 A 股，投资者通过会员提交相应委托。因此不得把沪深主板盘后固定价格交易描述为散户专属；实际分析仍要核验当时有效规则。

制度核验优先回到交易所当前规则页：

- [上海证券交易所交易规则（2026 年修订）](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)
- [深圳证券交易所交易规则（2026 年修订）](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)

## 5. 延迟与降级规则

### 5.1 行情延迟 15—30 分钟

当关键盘中行情延迟 15—30 分钟时：

1. 明示“盘中行情延迟 N 分钟”，列出最后 `as_of`。
2. 禁止给出“现在立即买入/卖出”或精确盘口价位。
3. 禁止判断延迟窗口内是否已突破、跌破、封板、炸板或完成回流。
4. 允许继续使用最近完成日线、公告和较慢变量做方向性分析。
5. 将结论降级为“条件观察”或“基于截至某时点的数据”。
6. 如果用户需要当下决策，索要本文件第 3.5 节所列截图；截图时间仍不足时继续保持降级。

### 5.2 数据完全缺失

- 缺个股当日行情：不做即时买卖结论，只做日线与逻辑层诊断，并索要个股分时图。
- 缺板块数据：不能认定个股是板块核心或逆势强势，索要板块分时/成分表现。
- 缺日 K：不能确定趋势、关键位和放量是否异常，索要至少 120 个交易日的前复权日 K。
- 缺公告原文：消息只标记为“待核验”，不进入硬性买卖条件。
- 缺交易日历：不得手算周末和法定假期；先用交易所或 Tushare 日历确认 D1。最终持有与复核安排只输出 D1—Dn 等相对标签。

## 6. DeepSeek 的允许用途

DeepSeek 是辅助语义模型，仅按需要调用，不要求每次分析都调用。

允许用途限于：

1. 新闻、公告的语义去重、聚类和分类；
2. 从原文中抽取时间、金额、产品、客户、产能、业绩、减持、解禁等字段；
3. 将经过核验的信息映射到“主题—产业集群—细分环节—公司角色”；
4. 生成多头、空头和替代解释，执行反方审查，指出证据缺口或可能的确认偏误。
5. 对已经由结构化数据筛选出的历史样本做描述性聚类，辅助发现可能重复的行为特征。

禁止用途：

- 生成或补全实时价格、成交量、资金流、财务数字；
- 把模型记忆当作公司业务、市场份额或公告事实；
- 独立证明公司稀缺性或产业关键性；
- 仅凭模型叙述生成“主力风格”，或用画像替代当前市场、主线、基本面和量价证据；
- 直接输出最终买入、卖出、仓位或持有窗口；
- 在来源冲突时自行裁决事实；
- 把模型推断写成“已确认的主力行为”。

DeepSeek 的结果必须标记为 `inferred`，关键抽取字段回到原文核对。最终决策由本 skill 根据结构化数据、事实核验、风险门槛和策略规则完成。

## 7. 密钥与隐私

- Agent 不读取、打印、复制、改写或提交任何明文 API 密钥文件。
- 除用户自行维护且已排除版本控制的仓库根目录 `my_api_key.md` 外，不把密钥复制到 skill、提示词、日志、报告、截图、其他 Markdown 或版本控制。
- Tushare MCP 在 Codex 初始化配置中提供。Codex 远程 MCP 的 `url` 不展开 `${ENV_VAR}`；若服务仅支持 URL token，应使用用户本机的私有 MCP 配置，不在仓库内生成或改写该配置。
- Tushare API 与 DeepSeek 由本地脚本自行解析凭证：先读取 `TUSHARE_TOKEN` 或 `DEEPSEEK_API_KEY`，环境变量不存在或为空时，再读取仓库根目录的 `my_api_key.md`。Agent 只调用脚本，不直接打开该文件。
- 凭证解析器只能返回“已配置/未配置”和来源类型等非敏感诊断；不得在标准输出、日志或异常消息中包含密钥值。
- 缺少凭证时报告“未配置”，不要询问用户在聊天中粘贴明文密钥。
- 工具输出疑似包含密钥时，不复述该内容，并停止将其传递给模型或外部服务。
- 发送到 DeepSeek 的文本遵循最小必要原则：移除账户金额、持仓账号、个人身份信息和无关上下文。

## 8. 分析前数据检查清单

每次进入决策前确认：

- [ ] 当前报告是盘前、盘中还是收盘后版本；
- [ ] 本次正式结论已使用新的 `analysis_as_of`，未把旧对话中的时效性判断直接当作当前事实，也未输出旧策略生命周期；
- [ ] 每项关键行情都有 `as_of` 和 `fetched_at`；
- [ ] 公告/新闻有 `published_at`，旧消息未被误认作新催化；
- [ ] 复权方式、币种、单位和市场方向一致；
- [ ] 延迟与缺失已触发相应降级；
- [ ] 截图包含名称、代码、日期、时间、坐标和量能；
- [ ] D1 未被误用为历史数据起点，历史长、中、短周期和可比事件样本已按需检查；

- [ ] 历史事件/行为样本已先定义规则并纳入全部符合条件的可得样本；
- [ ] 盘后或特殊时段数据已核验交易机制和参与者范围，未作账户身份归因；
- [ ] DeepSeek 只处理允许的语义任务，结果已标记为推断；
- [ ] 最终输出列明数据完整度和仍缺少的信息。
