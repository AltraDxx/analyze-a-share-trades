# A股短中波段决策

## 一个引擎，三种范围

三类请求共用“事件目标 → 所处阶段 → 当前动作 → 反馈验证 → 交易动作”引擎，只改变研究对象。Agent 自主选择最小分析范围，不要求用户选择模式，也不展示内部模式名。

- **持仓处置**：只研究用户给出的持仓及能改变持有、减仓或退出动作的证据；不扫描全市场、不生成候选池。成本、仓位和原始理由已提供时纳入。
- **指定股票买入**：只研究用户给出的股票并检查买入资格；除非用户同时要求替代标的，否则不寻找其他股票。
- **全市场机会发现**：只有用户未给候选而询问“买什么、有哪些机会、现在怎么办”，或明确要求全市场筛选时才执行。先用结构化数据和硬过滤得到少量候选，再逐只运行同一引擎；不得让模型逐只扫描全市场或用指标排名直接给买入结论。

混合请求按股票分别处理。只有扩大范围可能检验当前事件判断、改变风险边界或改变动作时才扩大，不为补齐流程机械分析大盘、板块、公告、分时或历史。

## 统一盘面事件推演引擎

“盘面事件”是市场、板块或个股从行为模式发生变化开始，到其目标完成、失败或被新事件取代的一段连续过程，不等于单条公告或当天涨跌。“想做什么”是对当前主导合力试图实现的盘面结果作最受公开行为支持的推断，不宣称读心或识别真实账户。

事件跨度由行为连续性决定，可以是两三天、一周或更久；交易决策仍以约 2—22 个交易日为默认窗口。不要把事件起点强行设为 D1，也不要每天根据当日数据另编故事。重新分析时先检查原事件是否延续、完成、失败或转化。

先用已有的最小事实推断整个事件想实现什么、已经做到哪里、眼下必须做什么，再取最有区分力的数据验证；不要先抓满数据、填写评估维度或套标签。

对每个决策对象：

1. 冻结用户要决定的动作、北京时间 `analysis_as_of`、研究对象、已有事实、代理变量和关键缺口；从行为模式的变化点识别待追踪事件，而不是任取固定回看区间。
2. 形成一个开放生成的主事件判断：最终想实现什么完整结果、当前处于什么阶段、现在正在或必须完成什么。不得从预设的“护盘、洗盘、派发”等选项中挑答案。只有竞争解释会预测不同痕迹、验证时点或用户动作时，才保留一个最强竞争解释。
3. 建立可向用户展示的简洁推断路径：关键行为序列与为什么偏偏此时发生 → 反常、连续或付出成本之处 → 若是普通波动本应出现却没有出现的反事实 → 哪个事件目标解释得更好 → 已完成步骤与当前动作。再写出下一项必要动作、市场反馈、验证期限、失效条件和对应用户动作。
4. 参与者、仓位、成本、期限、对手盘和流动性只在能解释关键行为或区分事件判断时使用，不是必填清单；用户持仓只影响执行，不能代替对市场、板块或个股事件的推断。
5. 只取得下一项最能检验推断链的证据。取数前明确它将支持、削弱或证伪哪一环及可能改变的动作；说不清信息增量就不取。
6. 将新证据与事前预测比较，判断当前动作是否有效、市场是否响应、事件是在推进、停滞、失败还是转化。最终给一个主判断，不把多种可能性菜单交给用户；确实无法区分时说明具体分歧和下一判别点。

相同痕迹、验证时点和动作的解释应合并。验证只判断截至 `analysis_as_of` 哪个事件解释最能贯通公开行为、哪些竞争解释已被证伪，不宣称证明真实账户的内心意图。

市场、板块、公告、日线、分时、筹码、资金代理和历史画像只是检验事件推断的证据源，不是平行打分维度。大盘、板块和个股可同时存在相互嵌套或冲突的事件；只展开会改变当前判断和动作的层级，不得机械填满三层。

“护盘、换仓、吸筹、试盘、洗盘、诱多、诱空、派发、兑现、轮动”等只是非穷尽的事后简称；只有推断路径、当前动作、必要反馈和证伪条件已经说明时才可使用，不得从标签出发寻找图形。

## 固定边界

- 买入或推荐只限沪深主板普通 A 股，排除创业板、科创板、北交所、ST、退市整理、停牌和明显低流动性股票；已有持仓即使不合格仍提供卖出诊断。
- 默认普通现金账户和约 2—22 个交易日窗口；不做用户未声明可交易的杠杆或衍生工具。30% 是组合净值灾难回撤上限，不是单股止损或常态容忍度。
- 每次重新核验时效性判断；旧对话中的事件判断只作待复核线索，先检查其延续、完成、失败或转化，不能当作当前事实。成本、仓位、原始理由和偏好等稳定事实可以保留；不计算跨问询交易日或已持有天数。
- 交易日提问时当日为 D1，非交易日时其后的首个交易日为 D1；收盘后最早只能下一交易日执行时写 D2，不重编号。D1 不是历史数据截断点；不计算、询问或输出已持有天数，不向用户换算未来自然日期。
- “操盘手、主力”只表示公开行为中可推断的主导合力，不表示识别真实账户或统一指挥者。资金流只是代理，不能证明账户行为。
- 不输出主观胜率、上涨概率、赔率或固定综合分，不强制推荐或排名；允许没有值得买的股票。单股只锁定一个主策略，不拼接宽松条件或因下跌改成长线持有。
- 不自动下单、不承诺收益；无用户风险预算时只给定性仓位。

## 按需证据模块

没有任何参考文件默认必读，也不得因要形成正式结论、买卖动作或最终答复而自动读取。只有模块能检验当前事件判断、解决关键数据边界或改变执行动作时才完整读取：

- 数据时点、来源、延迟、截图、特殊时段、凭证或模型：[data-access.md](references/data-access.md)
- 日线、分时、竞价或历史行为证据：[price-flow-evidence.md](references/price-flow-evidence.md)
- 市场级、板块级、主线或产业角色证据：[market-sector-evidence.md](references/market-sector-evidence.md)
- 公告和其他信息能支持或证伪推断链：[event-evidence.md](references/event-evidence.md)
- 仅在全市场机会发现时生成候选：[discover-candidates.md](references/discover-candidates.md)
- 策略、组合、仓位、D1、T+1、涨跌停或特殊执行：[execution.md](references/execution.md)

一次扩展一个最有区分力的证据源；合格单一来源通常足够，关键冲突才交叉核验。新增证据不再改变事件判断、动作或风险边界时停止。同日已有 `market_game_snapshot` 时只做新鲜度检查；交易阶段、重大信息或失效条件未变化就复用，不得跨北京时间交易日沿用。

优先运行模块引用的脚本，把原始大表写入文件，只将必要特征、异常、元数据和证据引用送入上下文。从仓库根目录优先使用 `./.venv/bin/python`，不修改全局 Python 环境。

## 风险、执行与输出

- 关键盘中数据缺失且会改变即时动作时，先给日线级暂定结论，再精确索要缺失截图；不补造事实。来源冲突先核对时点、复权、单位和口径，不挑选有利数据。
- 普通 A 股遵守 T+1。涨跌停先假设能够成交并判断 D1 应否交易；应交易时给尝试方案且不保证成交，未成交或部分成交时按真实仓位给 D2 条件预案。停牌或已无适用交易时段等硬限制按事实处理。
- 事件判断尚未充分区分不等于价格必跌。未持仓默认等待；只有当前必要动作已经开始、失效边界清晰且 T+1 风险可管理时，才可给定性试探。已有持仓不得仅因“意图不知道”机械清仓，应根据事件是否失效、当前动作是否失败和账户风险决定持有、减仓或退出；分歧路径会造成不可管理风险时优先降低暴露。
- 用户知情后仍明确要求继续时才进入纯数据/信息降级分析；置顶披露无法可靠判断盘面事件目标，不得把降级结果包装成主力判断。

结论置顶写 `analysis_as_of`、D1、股票名称与代码及用户动作。紧接着且在任何行情指标、个股列表或证据明细之前，用四个可见短项回答：`事件要做什么`，写完整目标结果，不能只写“修复、洗盘、派发”等标签；`处于什么阶段`，写已完成与仍缺的步骤；`它现在要做什么`，写盘面当前动作，不得用“用户等待/买入”替代；`推断路径`，写事件起点、关键序列、反事实及主判断为何更优。随后才写当前动作是否得到反馈、下一项必要痕迹及验证期限、一个主策略、失效与退出条件。发送前检查结论后的首个内容块必须包含上述四个同名短项，缺一项就重写。竞争解释只在有动作相关分歧时出现；不输出思维流水账、无关数据或空栏目。

持仓问题直接回答持有、持有但不加仓、减仓、条件卖出、卖出或退出至空仓；指定买入问题直接回答值得买、条件值得买、等待或不买。全市场机会发现还要简述候选来源并列出全部深析后值得买或条件值得买的股票，也允许明确“当前没有值得买的股票”。
