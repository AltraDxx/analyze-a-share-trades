# A股短中波段决策

## 一个引擎，三种范围

三类请求共用“意图假设 → 区分性取证 → 证伪或更新 → 交易动作”引擎，只改变研究对象。Agent 自主选择最小分析范围，不要求用户选择模式，也不展示内部模式名。

- **持仓处置**：只研究用户给出的持仓及能改变持有、减仓或退出动作的证据；不扫描全市场、不生成候选池。成本、仓位和原始理由已提供时纳入。
- **指定股票买入**：只研究用户给出的股票并检查买入资格；除非用户同时要求替代标的，否则不寻找其他股票。
- **全市场机会发现**：只有用户未给候选而询问“买什么、有哪些机会、现在怎么办”，或明确要求全市场筛选时才执行。先用结构化数据和硬过滤得到少量候选，再逐只运行同一引擎；不得让模型逐只扫描全市场或用指标排名直接给买入结论。

混合请求按股票分别处理。只有扩大范围可能区分当前假设、改变风险边界或改变动作时才扩大，不为补齐流程机械分析大盘、板块、事件、分时或历史。

## 统一意图假设验证引擎

先用已有的最小事实推断主导资金可能在做什么，再取最有区分力的数据验证；不要先抓满数据、填写评估维度或套标签。

对每个决策对象：

1. 冻结用户要决定的动作、北京时间 `analysis_as_of`、已有事实、代理变量、推断和关键缺口。
2. 形成一个主假设和最强竞争假设；通常两个足够。合理时把“普通市场波动或没有特殊主导优势”作为零假设。第三条路径只有在会预测不同痕迹、验证时点或动作时才加入。
3. 每个假设写清：参与者及仓位、成本、期限、事件、流动性或风险约束；可能目标与动作；所需对手盘；预期何时留下哪些价格、成交、相对强弱、板块扩散或承接痕迹；证伪条件；成立时的用户动作。
4. 只取得下一项最能区分假设的证据。取数前明确它将支持、削弱或证伪哪个假设及可能改变的动作；说不清信息增量就不取。
5. 将新证据与事前预测比较，支持、削弱或淘汰假设。一个机制明显更符合公开痕迹时形成条件动作；不同机制导向同一动作时写“具体意图无需判断”；剩余机制导向不同动作且无法可靠区分时写“意图不知道”。

相同痕迹、验证时点和动作的解释应合并。验证只判断截至 `analysis_as_of` 哪个机制最能解释公开行为、哪些竞争解释已被证伪，不宣称证明真实账户的内心意图。

市场、板块、事件、日线、分时、筹码、资金代理和历史画像只是检验假设的证据源，不是平行打分维度。大盘、板块和个股可相互领先或反馈，假设可以跨层，但不得机械填满三层。

“护盘、换仓、吸筹、试盘、洗盘、诱多、诱空、派发、兑现、轮动”等只能在参与者约束、动作、对手盘、预期痕迹和反馈已说明后作简称；不得从标签出发寻找图形。

## 固定边界

- 买入或推荐只限沪深主板普通 A 股，排除创业板、科创板、北交所、ST、退市整理、停牌和明显低流动性股票；已有持仓即使不合格仍提供卖出诊断。
- 默认普通现金账户和约 2—22 个交易日窗口；不做用户未声明可交易的杠杆或衍生工具。30% 是组合净值灾难回撤上限，不是单股止损或常态容忍度。
- 每次重新核验时效性判断；旧对话只保留成本、仓位、原始理由和偏好等稳定事实。不计算跨问询交易日，不维护“原策略失效/恢复/到期”等旧策略生命周期。
- 交易日提问时当日为 D1，非交易日时其后的首个交易日为 D1；收盘后最早只能下一交易日执行时写 D2，不重编号。D1 不是历史数据截断点；不计算、询问或输出已持有天数，不向用户换算未来自然日期。
- “操盘手、主力”只表示公开行为中可推断的主导合力，不表示识别真实账户或统一指挥者。资金流只是代理，不能证明账户行为。
- 不输出主观胜率、上涨概率、赔率或固定综合分，不强制推荐或排名；允许没有值得买的股票。单股只锁定一个主策略，不拼接宽松条件或因下跌改成长线持有。
- 不自动下单、不承诺收益；无用户风险预算时只给定性仓位。

## 按需证据模块

没有任何参考文件默认必读，也不得因要形成正式结论、买卖动作或最终答复而自动读取。只有模块能区分当前假设、解决关键数据边界或改变执行动作时才完整读取：

- 数据时点、来源、延迟、截图、特殊时段、凭证或模型：[data-access.md](references/data-access.md)
- 日线、分时、竞价或历史行为证据：[price-flow-evidence.md](references/price-flow-evidence.md)
- 市场级、板块级、主线或产业角色证据：[market-sector-evidence.md](references/market-sector-evidence.md)
- 事件能支持或证伪假设：[event-evidence.md](references/event-evidence.md)
- 仅在全市场机会发现时生成候选：[discover-candidates.md](references/discover-candidates.md)
- 策略、组合、仓位、D1、T+1、涨跌停或特殊执行：[execution.md](references/execution.md)

一次扩展一个最有区分力的证据源；合格单一来源通常足够，关键冲突才交叉核验。新增证据不再改变假设、动作或风险边界时停止。同日已有 `market_game_snapshot` 时只做新鲜度检查；交易阶段、重大事件或失效条件未变化就复用，不得跨北京时间交易日沿用。

优先运行模块引用的脚本，把原始大表写入文件，只将必要特征、异常、元数据和证据引用送入上下文。从仓库根目录优先使用 `./.venv/bin/python`，不修改全局 Python 环境。

## 风险、执行与输出

- 关键盘中数据缺失且会改变即时动作时，先给日线级暂定结论，再精确索要缺失截图；不补造事实。来源冲突先核对时点、复权、单位和口径，不挑选有利数据。
- 普通 A 股遵守 T+1。涨跌停先假设能够成交并判断 D1 应否交易；应交易时给尝试方案且不保证成交，未成交或部分成交时按真实仓位给 D2 条件预案。停牌或已无适用交易时段等硬限制按事实处理。
- “意图不知道”时，未持仓默认保持空仓；已有持仓且用户要求明确动作时，默认按可执行规则退出至空仓。这是无法管理分歧路径的风险偏好，不是断言价格必跌。
- 用户知情后仍明确要求继续时才进入纯数据/事件降级分析；置顶披露无法可靠判断主导资金意图，不得把降级结果包装成主力判断。

结论置顶写 `analysis_as_of`、D1、股票名称与代码及动作。随后简洁区分：决定动作的事实；主假设与最强竞争假设；判别证据如何支持、削弱或证伪它们；一个主策略、下一确认、失效与退出条件；必要的数据缺口和执行风险。只在实际需要时写 D2 和持有窗口，不输出与动作无关的完整研究过程或空栏目。

持仓问题直接回答持有、持有但不加仓、减仓、条件卖出、卖出或退出至空仓；指定买入问题直接回答值得买、条件值得买、等待或不买。全市场机会发现还要简述候选来源并列出全部深析后值得买或条件值得买的股票，也允许明确“当前没有值得买的股票”。
